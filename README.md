# LeafLens — Plant Disease Detection Streamlit App

This UI is designed around the uploaded notebook **Plant Disease Prediction — MobileNetV2 Built & Trained From Scratch**.

## What the notebook does (used to design this app)

- Manually builds a MobileNetV2-style backbone; it does not use pretrained ImageNet weights or `keras.applications`.
- Uses RGB images resized to **224 × 224**.
- The model includes a `preprocess` Lambda layer that maps pixels from **[0, 255] to [-1, 1]**.
- Uses GlobalAveragePooling2D, Dropout(0.3), and a Dense softmax output.
- Class labels are generated by sorting the PlantVillage class folder names alphabetically.
- Saves the best checkpoint to `best_mobilenetv2_scratch.keras` in Google Drive.

## Files you need

Put these files in the same folder:

```text
plant_disease_streamlit/
├── app.py
├── requirements.txt
├── prepare_classes.py
├── best_mobilenetv2_scratch.keras   # copy this from your Google Drive checkpoint
```

**The notebook itself was uploaded, but the trained `.keras` model checkpoint was not.** The app cannot make real predictions until you copy that checkpoint into this folder.

```python
class_names = sorted(df["class_name"].unique())
```

## Important preprocessing detail

The notebook places normalization inside the model:

```python
layers.Lambda(preprocess, name="preprocess")
```

where:

```python
return (x / 127.5) - 1.0
```

Therefore, `app.py` resizes and converts the uploaded image to RGB and passes pixel values in the 0–255 range. **Do not normalize the uploaded image a second time** before passing it to this model.

The model's augmentation layer is part of the model graph, but Keras runs it in inference mode during `model.predict()`.

## Troubleshooting

### Model file not found
Check that the filename is exactly `best_mobilenetv2_scratch.keras` and it is beside `app.py`.

### Class labels missing
Run `prepare_classes.py` as shown above. It must use the same PlantVillage `raw/color` folder and sorted class names used during training.

### Model output count does not match labels
Your model and `class_names.json` were made from different class lists, or the JSON order was changed. Regenerate the JSON from the original dataset folder used in the notebook.

### Error loading the Lambda layer
The notebook uses a Lambda layer with a Python function named `preprocess`. The app registers that function as a custom object and loads with `compile=False` and `safe_mode=False`. Use a compatible TensorFlow/Keras version if the checkpoint was saved with a substantially different version.

### TensorFlow installation is difficult
Use a Python version supported by the TensorFlow release you install. If pip reports no compatible TensorFlow wheel, install a supported Python version (commonly Python 3.10 or 3.11) in a fresh virtual environment and retry.

## Limitations

The notebook does not define a treatment recommendation system. This app therefore reports the model's predicted class and probabilities only; it does not invent treatments. The confidence score is the model's softmax output, not a calibrated probability of a confirmed field diagnosis.


## Optional: add a separate plant-image validator

The original disease classifier always chooses one of its known disease classes.
To reduce unsupported predictions, this version can run a **separate binary
validator first**. It does not alter or retrain your hand-built MobileNetV2
disease classifier.

### What the validator checks

It learns two categories:

- `supported_leaf`: leaf photos from the plant categories represented in your PlantVillage training dataset.
- `unsupported`: non-leaf photos (people, objects, pets, scenery, etc.) AND leaf/plant photos from species not represented by your disease classifier.

The validator is optional. If its model file is absent, the disease app still runs, but it clearly warns that unsupported images cannot be reliably rejected.

### Step 1 — Prepare example images

Create this folder structure:

```text
validator_dataset/
├── supported_leaf/
│   ├── leaf_001.jpg
│   ├── leaf_002.jpg
│   └── ...
└── unsupported/
    ├── other_plant_001.jpg
    ├── non_leaf_001.jpg
    └── ...
```

Use a varied and balanced collection. Include:
- Different supported crops and disease conditions in `supported_leaf`.
- Many other plant species, flowers, grass, tree leaves, and non-leaf images in `unsupported`.
- Different backgrounds, lighting, camera distances, and image qualities.

Do not put the same image (or near-duplicate versions) in both training and validation. Keep some completely unseen images for your own final test. A validator trained only on a few examples will not generalize reliably.

### Step 2 — Train the validator

Open a terminal in this project folder and run:

```bash
python train_validator.py --dataset "C:/path/to/validator_dataset" --epochs 12
```

The training script uses an ImageNet-pretrained MobileNetV2 as a **separate binary image validator**. The first training run may download pretrained weights, so an internet connection may be needed. This does not change the original scratch-trained disease model.

It creates:

```text
plant_validator.keras
```

Move/keep that file beside `app.py`.

### Step 3 — Run the app

```bash
streamlit run app.py
```

The app now checks the uploaded image first:
- **Supported:** continue to the original disease classifier.
- **Review:** show a warning and mark the disease prediction as unreliable.
- **Unsupported:** stop before running the disease classifier.

The current thresholds are near the top of `app.py`:

```python
VALIDATOR_UNSUPPORTED_THRESHOLD = 0.70
VALIDATOR_REVIEW_THRESHOLD = 0.40
```

They are starting values, not scientifically validated cut-offs. Tune them using a separate validation set and inspect false accepts (unsupported photos allowed through) and false rejects (valid leaf photos blocked).

### Important limitation

This is a learned screening gate, not a perfect guarantee. It may still accept an unsupported plant or reject a valid supported leaf, especially if your training examples are too few or too similar. Test with unseen examples before demonstrating it as reliable. A softmax confidence threshold from the disease classifier alone is not a dependable unknown-image detector.
